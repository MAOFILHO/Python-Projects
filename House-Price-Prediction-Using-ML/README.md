# House Price Prediction Project

The House Price Prediction project demonstrates the development of a machine learning pipeline for predicting house prices based on property features. The project follows a structured approach to handle data preprocessing, model training, evaluation, and deployment, ensuring a robust and efficient workflow.

Key points:
* Data loading and preprocessing.
* Training and evaluating a regression model.
* Saving the model and preprocessing steps for future use.
* Deploying the trained model using a Streamlit application.

---

## 📂 Repository Structure

```text
├── train.py                # Core machine learning training and serialization pipeline
├── app.py                  # Client-facing interactive Streamlit web dashboard
├── AmesHousing.csv         # Comprehensive historical housing records database
├── house_price_model.pkl   # Serialized Linear Regression model parameters (Generated by train.py)
├── preprocessor.pkl        # Serialized ColumnTransformer preprocessing state (Generated by train.py)
└── .gitignore              # Git architecture ignore mapping
```

---

## 🛠️ Application Components & Script Architecture

### 1. `train.py` (The Machine Learning Engine)
This standalone script governs the entire machine learning asset lifecycle and backend processing logic. It handles:
* **Data Ingestion:** Reads the raw source observations straight from the localized `AmesHousing.csv` payload.
* **Structural Transformation Pipelines:** Automatically isolates data schemas into continuous features (`int64`, `float64`) and textual arrays (`object`, `str`). Continuous tracking fields undergo median imputation combined with variance-balancing standard scaling. Textual indices route through most-frequent replacement metrics and fallback-safe categorical tracking via Scikit-Learn's `OneHotEncoder`.
* **State Preservation:** Fits the parameters globally to a unified Scikit-Learn `ColumnTransformer`, isolates data splits into an 80/20 train/test profile, and trains a multi-variable `LinearRegression` configuration.
* **Serialization:** Compiles and flushes binary representations of the pipeline elements (`preprocessor.pkl` and `house_price_model.pkl`) to disk via `joblib` so they are immediately available for downstream applications.

### 2. `app.py` (The Interactive Streamlit Dashboard)
This script operates as the client-facing front-end layer designed to interface seamlessly with your trained weights:
* **Asset Loading:** Imports the pre-compiled `.pkl` layout maps immediately upon boot, avoiding computing runtime steps on every slider or entry mutation.
* **Data Matrix Syncing:** Captures precise metric controls tailored to property traits (such as Lot Area, Overall Quality, Year Built, Living Area square footage) from client input elements.
* **Pipeline Vectorization:** Bundles entry parameters on the fly into a target Pandas DataFrame mapping exact structural keys, runs the static pre-compiled vector grid across it, and displays instant, live-calculated real estate valuation quotes.

## ⚙️ Local Environment Configuration

Isolate your execution space from system-wide library configurations or global manager path distortions on macOS by spinning up a clean environment anchored explicitly on Python `3.11`.

### 1. Build a Targeted Python 3.11 Virtual Environment
Initialize a designated `.venv` folder in the project workspace root using one of the primary macOS setup paths below:

* **Method A: Direct via localized terminal path binary mapping**
  ```bash
  python3.11 -m venv .venv
  ```

* **Method B: Via explicit version alignment when managing environments through pyenv**
  ```bash
  pyenv local 3.11.15
  python -m venv .venv
  ```

### 2. Activate the Isolated Shell
```bash
source .venv/bin/activate
```
*(Verify activation: Look for the `(.venv)` string prepended to your active shell prompt).*

### 3. Ingest System Dependencies
Install the exact computational libraries required for modeling, scaling, tracking, and serving into your environment frame:
```bash
pip install pandas scikit-learn streamlit watchdog joblib
```

## 🚀 Execution & Serving Guide

### ⚠️ CRITICAL EXECUTION REQUIREMENT
You **must** run `train.py` to process features and generate model artifacts **before** initializing `app.py`. The Streamlit application will fail to launch if the required `.pkl` configuration binaries are missing.

### Step 1: Initialize the Model Pipeline
Compile features, evaluate the model performance profile, and generate the static binary dependencies by processing the training script:
```bash
python train.py
```
*Expected Terminal Output Confirmation:* `✅ Training complete! Model and preprocessor saved.`

### Step 2: Spin Up the Visual App Framework
Launch the server loop via the environment execution module flag to avoid terminal shell path collisions:
```bash
python -m streamlit run app.py
```

Once the framework spins up, open your web browser and head over to `http://localhost:8501` to use the interactive application interface.
